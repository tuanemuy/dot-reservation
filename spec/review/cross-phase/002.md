# クロスフェーズ検証: 認証アカウント共有モデルへの変更

## 変更概要

ADR-002 を「顧客とメンバーの認証アカウント分離」から「認証アカウント共有」に変更。同一メールアドレスで顧客とメンバーの両方を利用可能にした。

## 変更されたファイル

- spec/adr/002-separate-customer-member-auth.md — 方針変更
- spec/domains/auth.md — 登録フロー、停止/BAN 設計、cleanupAuthUserIfOrphaned 追加
- spec/usecases/auth.md — deleteCustomer/deleteMemberAccount/suspendCustomer/reactivateCustomer の変更、cleanupAuthUserIfOrphaned 追加
- spec/scenario/customer-account.md — 登録補足の変更
- spec/scenario/tenant-member-account.md — 登録補足の変更
- spec/pages/index.md — 顧客プロフィール作成ページ、管理画面プロフィール作成ページの追加
- spec/testcases/auth/authIntegration.md — テストケース更新
- spec/testcases/auth/cleanupAuthUserIfOrphaned.md — 新規テストケース

## トレーサビリティ検証

### シナリオ → 設計の整合性

| シナリオ変更 | 設計の対応 | 結果 |
|---|---|---|
| 顧客登録 — メール登録済み時にログインを促す | auth.md クロス登録フロー | OK |
| メンバー登録 — メール登録済み時にログインを促す | auth.md クロス登録フロー | OK |
| ログイン後にプロフィール未作成なら作成ページへ | auth.md セッション検証、usecases/auth.md ルートローダーパターン | OK |
| 顧客停止がメンバーに影響しない | auth.md 停止/BAN 設計 | OK |
| アカウント削除で他方が維持される | cleanupAuthUserIfOrphaned ユースケース | OK |

### ページ設計 → シナリオの整合性

| 追加ページ | 対応するシナリオ | 結果 |
|---|---|---|
| 顧客プロフィール作成ページ (/customer/setup) | 顧客アカウント登録（クロス登録フロー） | OK |
| 管理画面プロフィール作成ページ (/admin/setup) | メンバーアカウント登録（クロス登録フロー） | OK |

### ユースケース → ドメインモデルの整合性

| ユースケース変更 | ドメインモデルの対応 | 結果 |
|---|---|---|
| suspendCustomer — authProvider.banUser 削除 | Customer.status で停止管理（既存） | OK |
| reactivateCustomer — authProvider.unbanUser 削除 | Customer.status で再開管理（既存） | OK |
| deleteCustomer — cleanupAuthUserIfOrphaned 追加 | AuthProvider.deleteUser, CustomerRepository, MemberRepository | OK |
| deleteMemberAccount — cleanupAuthUserIfOrphaned 追加 | AuthProvider.deleteUser, CustomerRepository, MemberRepository | OK |

## アーキテクチャ適合性

| チェック項目 | 結果 | 詳細 |
|---|---|---|
| ドメイン層は better-auth に依存しない | OK | 変更なし |
| ビジネスロジックはドメイン層に配置 | OK | Customer.suspend/reactivate の振る舞いは既存。auth BAN を削除しただけ |
| 集約間は ID で参照 | OK | cleanupAuthUserIfOrphaned は authUserId で両ドメインを参照 |
| ドメイン間の非循環依存 | OK | cleanupAuthUserIfOrphaned は Customer と Member の両リポジトリを使用するが、これはユースケース層のオーケストレーション |

## 実装可能性

| チェック項目 | 結果 | 詳細 |
|---|---|---|
| cleanupAuthUserIfOrphaned のシグネチャ | OK | 入力 authUserId: string、依存: customerRepository, memberRepository, authProvider |
| 停止/BAN の二層モデル | OK | ドメインレベル（Customer.status）と auth レベル（better-auth BAN）が明確に分離 |
| クロス登録フローの実装 | OK | signUp エラー → ログイン誘導 → loader リダイレクト → setup ページ のフロー明記 |
| setup ページの入力 | OK | 顧客: 表示名のみ、メンバー: 氏名のみ。メールは auth ユーザーから取得 |

## 検出された問題

なし。認証アカウント共有モデルへの変更は全フェーズで整合しており、実装に必要な情報が揃っている。
