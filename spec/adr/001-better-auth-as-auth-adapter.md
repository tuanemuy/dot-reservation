# ADR-001: better-auth を認証アダプターとして採用

## ステータス

承認済み

## コンテキスト

本システムは顧客、テナントメンバー、プラットフォーム管理者の3種類のユーザーに対して認証機能を提供する必要がある。認証機能にはユーザー登録、ログイン、セッション管理、メール確認、パスワードリセットが含まれる。

ヘキサゴナルアーキテクチャにおいて、認証は外部インフラストラクチャとして位置づけられ、ポートを通じてアプリケーション層から利用される。

## 決定

認証ライブラリとして better-auth を採用し、アダプターとしてヘキサゴナルアーキテクチャに統合する。

- **サーバー側**: better-auth の HTTP ハンドラを `/api/auth/*` にマウントし、`AuthProvider` ポートを通じてセッション検証やユーザー管理を行う
- **クライアント側**: better-auth の React クライアント SDK を直接使用して、サインアップ・サインイン・サインアウト等の操作を行う
- **DB**: better-auth が管理するテーブル（users, sessions, accounts, verifications）を Drizzle ORM アダプター経由で SQLite に永続化する
- **プラグイン**: admin プラグインを使用し、プラットフォーム管理者のユーザー管理（BAN/解除）を実現する

## 検討した代替案

### 1. 自前実装

認証機能を全て自前で実装する。

**不採用理由**: パスワードハッシュ、セッション管理、CSRF 対策、メール確認トークン管理等のセキュリティ要件を正しく実装するコストが高い。車輪の再発明になる。

### 2. Auth.js (NextAuth)

Auth.js を認証ライブラリとして使用する。

**不採用理由**: Next.js エコシステムに最適化されており、React Router v7 Framework mode との統合がスムーズでない。

### 3. Lucia Auth

Lucia Auth を使用する。

**不採用理由**: 2024年にメンテナンス終了がアナウンスされた。

### 4. better-auth organization プラグイン

better-auth の organization プラグインを使ってテナントメンバーシップ管理も better-auth に委譲する。

**不採用理由**: organization プラグインの member モデルは汎用的で、本システムの Member ドメイン（admin/staff ロール、スタッフプロフィール連携、招待フロー）の要件を満たさない。ドメイン固有のビジネスロジックはドメイン層で管理すべき。

## 影響

- better-auth が管理するテーブル（users, sessions, accounts, verifications）がデータベースに追加される
- 認証関連のエンドポイント（`/api/auth/*`）は better-auth がハンドリングするため、React Router のルーティングから除外される
- ドメイン層は `AuthProvider` ポートに依存するが、better-auth 自体には依存しない（交換可能）
- フロントエンドは better-auth クライアント SDK に直接依存する
- メール送信基盤が必要（確認メール、パスワードリセットメール）
