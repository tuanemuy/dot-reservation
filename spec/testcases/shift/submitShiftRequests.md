# submitShiftRequests - シフト希望を提出する テストケース

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| スタッフプロフィールが存在する | 複数日の勤務希望（type="work", startTime, endTime 付き）を提出する | シフト希望が正常に登録される | 未実装 |
| スタッフプロフィールが存在する | 休み希望（type="off"）を含むシフト希望を提出する | 休み希望が正常に登録される（timeRange は null） | 未実装 |
| スタッフプロフィールが存在する | 備考（note）付きのシフト希望を提出する | 備考が正常に保存される | 未実装 |
| スタッフプロフィールが存在する | 備考なし（note=null）のシフト希望を提出する | note が null で正常に登録される | 未実装 |
| スタッフプロフィールが存在する | 勤務希望と休み希望を混在させたシフト希望を提出する | すべての希望が正常に登録される | 未実装 |
| スタッフプロフィールが存在し、同期間のシフト希望が既に提出済みである | 同期間のシフト希望を再度提出する | 既存の希望が上書き（削除後に新規作成）される | 未実装 |
| スタッフプロフィールが存在し、同期間のシフト希望が既に提出済みである | 異なる内容で再提出する | 以前の希望は削除され、新しい希望のみが保存される | 未実装 |
| シフト希望が正常に提出された | 提出完了後 | 管理者にシフト希望提出の通知が送信される（shiftRequest.submitted イベント） | 未実装 |
| スタッフプロフィールが存在する | 空の requests 配列を提出する | 正常に処理される（希望なしとして扱われる）か、バリデーションエラーとなる | 未実装 |
| スタッフプロフィールが存在する | 勤務希望（type="work"）で startTime, endTime を省略して提出する | バリデーションエラーがスローされる | 未実装 |
| スタッフプロフィールが存在する | 勤務希望で startTime が endTime より後の値で提出する | バリデーションエラーがスローされる | 未実装 |
| 存在しない staffProfileId を指定する | シフト希望を提出する | NotFoundError がスローされる | 未実装 |
| スタッフプロフィールが存在する | 同じ日付の希望が requests 内に重複して含まれている | 適切にエラーとなるか、最後の値が採用される | 未実装 |
