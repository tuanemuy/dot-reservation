# createShift - シフトを登録する テストケース

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| スタッフプロフィールが存在し、営業時間内である | 有効な日付、開始時刻、終了時刻、recurring=false を指定してシフトを登録する | 単発シフトが正常に作成され、shiftIds に1件のIDが返される | 未実装 |
| スタッフプロフィールが存在し、営業時間内である | recurring=true、recurringEndDate を4週間後に指定してシフトを登録する | 毎週繰り返しシフトが作成され、終了日までの全週分の shiftIds が返される | 未実装 |
| スタッフプロフィールが存在し、営業時間内である | recurring=true、recurringEndDate を1週間後に指定してシフトを登録する | 2件のシフト（当週と翌週）が作成され、shiftIds に2件のIDが返される | 未実装 |
| 繰り返しシフトを作成した場合 | 作成された各シフトを確認する | すべてのシフトに同じ recurringGroupId が設定されている | 未実装 |
| 単発シフトを作成した場合 | 作成されたシフトを確認する | recurringGroupId が null である | 未実装 |
| スタッフプロフィールが存在する | 営業時間外の時間帯を指定してシフトを登録する | バリデーションエラーがスローされる | 未実装 |
| スタッフプロフィールが存在する | 開始時刻が営業時間内だが、終了時刻が営業時間外となるシフトを登録する | バリデーションエラーがスローされる | 未実装 |
| スタッフプロフィールが存在し、同日同時間帯に既存シフトがある | 既存シフトと完全に重複する時間帯でシフトを登録する | ConflictError がスローされる | 未実装 |
| スタッフプロフィールが存在し、同日に既存シフトがある | 既存シフトと部分的に重複する時間帯でシフトを登録する | ConflictError がスローされる | 未実装 |
| スタッフプロフィールが存在し、同日に既存シフトがある | 既存シフトと重複しない時間帯でシフトを登録する | 正常にシフトが作成される | 未実装 |
| スタッフプロフィールが存在する | 開始時刻が終了時刻より後の値でシフトを登録する | バリデーションエラーがスローされる（TimeRange: start < end） | 未実装 |
| スタッフプロフィールが存在する | 開始時刻と終了時刻が同じ値でシフトを登録する | バリデーションエラーがスローされる（TimeRange: start < end） | 未実装 |
| スタッフプロフィールが存在する | 15分単位でない時刻を指定してシフトを登録する | バリデーションエラーがスローされる（TimeOfDay は15分単位） | 未実装 |
| スタッフプロフィールが存在する | recurring=true だが recurringEndDate が null のシフトを登録する | バリデーションエラーがスローされるか、適切なデフォルト動作が行われる | 未実装 |
| スタッフプロフィールが存在する | recurring=true で recurringEndDate が開始日より前の日付でシフトを登録する | バリデーションエラーがスローされる | 未実装 |
| 繰り返しシフトを作成する際、一部の週に既存シフトとの重複がある | recurring=true で複数週分のシフトを登録する | ConflictError がスローされ、シフトは1件も作成されない（トランザクション整合性） | 未実装 |
| shift.created ドメインイベントの発行 | シフトを正常に登録する | shift.created イベントが発行される | 未実装 |
